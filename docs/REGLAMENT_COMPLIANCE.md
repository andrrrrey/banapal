# Сверка движка контроля с «Регламентом ведения CRM Bitrix24 — дела»

Статус реализации детерминированного движка регламента (`app/services/reglament.py`)
относительно пунктов регламента. Легенда: ✅ реализовано · ⚠️ частично / через
общий параметр · ❌ требует сопоставления полей воронки Заказчика (Этап E).

## Этапы и сроки (раздел 4)

| Этап регламента | Норматив | Статус | Комментарий |
|---|---|---|---|
| Новое обращение / Новый заказ | первый контакт ≤ 15 мин (раб. время) | ✅ | `overdue_contact`, порог настраивается в админ-панели; считается по рабочему календарю |
| Обращение взято в работу / Квалификация | до 1 суток | ⚠️ | покрывается общим порогом «зависшей сделки»; отдельного норматива «1 сутки» нет |
| Ожидание заказа / Квалифицирован | до даты следующего действия | ⚠️ | контролируется через «нет дела» и «без повторного касания»; дедлайн по дате дела не проверяется |
| Счёт на предоплату | до 5 дней | ⚠️ | покрывается общим порогом «зависшей» (по умолч. 5 дней); отдельного правила по счёту нет |
| Комплектация / Собран / Доставляется / Получен | по процессу, без дела допустимо | ✅ | эти этапы не требуют задачи (`STAGE_TASK_RULE` их не включает) |
| Отказ | обязательно с причиной | ❌ | причина отказа из Битрикс пока не выгружается — правило «отказ без причины» не проверяется |
| Спам | нельзя переводить живую сделку | ✅ | эвристика: был звонок → выносится на проверку руководителю |
| Успешно реализовано | финал | ✅ | распознаётся как терминальный (по семантике/названию), исключается из нарушений |

Распознавание этапов устойчиво к реальным данным Битрикс: стадии приходят кодами
(`C10:NEW`, `LOSE`, `WON`) и резолвятся в названия (`crm.status.list`), а
терминальные/новые этапы определяются по названию, ключевым словам и семантике
Битрикс (P/S/F).

## Правила постановки дел (раздел 6)

| Правило | Статус | Комментарий |
|---|---|---|
| Дело обязательно на 5 рабочих этапах | ✅ | `no_task` по `STAGE_TASK_RULE` (после резолва названий стадий) |
| Без дела можно на Комплектация/Собран/Доставляется/Получен | ✅ | эти этапы исключены из требования задачи |

## Обязательные поля карточки (раздел 5)

| Поле | Статус |
|---|---|
| Имя клиента | ✅ (название сделки) |
| Телефон | ✅ подтягивается у контакта сделки (`crm.contact.list`) |
| Источник обращения | ✅ (`SOURCE_ID`) |
| Сумма (ориентировочная) | ✅ (`OPPORTUNITY`) |
| UTM-метки | ✅ (`UTM_SOURCE`) |
| Тип клиента / суть запроса / товары / сроки / комментарий / причина отказа | ❌ требуется сопоставление пользовательских полей воронки Заказчика |

Набор обязательных полей настраивается в админ-панели регламента.

## Нарушения и санкции (раздел 9)

| Нарушение по регламенту | Статус | Правило движка |
|---|---|---|
| Не взятое вовремя новое обращение | ✅ | `overdue_contact` |
| Отсутствие дела по активной сделке | ✅ | `no_task` |
| Незаполненные обязательные поля | ⚠️ | `fields` (по доступным полям, см. выше) |
| Возможный дубль | ✅ | `dup` (по телефону/e-mail, правило настраивается) |
| Зависшая сделка без движения | ✅ | `stuck` |
| Лид без повторного касания | ✅ | `no_recontact` |
| Перевод живой сделки в спам | ✅ | эвристика на проверку руководителю |
| Перевод в отказ «для чистоты воронки» | ✅ | эвристика на проверку руководителю |
| Перевод в отказ без причины | ❌ | причина отказа не выгружается |
| Отсутствие комментария по коммуникации | ❌ | нет данных о коммуникациях/комментариях из Битрикс |
| Работа с клиентом вне CRM | ❌ | вне возможностей системы (нет данных вне CRM) |
| Неверный этап сделки | ❌ | требует бизнес-правил соответствия этапа реальному статусу |

## Что нужно от Заказчика для полного соответствия (Этап E)

1. Сопоставить пользовательские поля воронки: тип клиента, суть запроса, товары/
   категории, сроки, причина отказа — чтобы включить их в контроль полей и правило
   «отказ без причины».
2. Подтвердить названия этапов воронки (совпадают ли с регламентом) — при
   необходимости уточнить `STAGE_TASK_RULE` и нормативы по этапам.
3. При необходимости — раздельные нормативы по этапам (1 сутки на квалификацию,
   5 дней на счёт) вместо общего порога «зависшей сделки».
