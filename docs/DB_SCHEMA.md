# Схема базы данных

СУБД: PostgreSQL 16. Модели: `backend/app/models/`. Миграции: Alembic
(`backend/alembic/`), применяются автоматически при старте `api`.

## Таблицы

### CRM / регламент (`models/crm.py`)
- **deals** — сделки единой воронки: клиент, ref, источник, кампания, UTM, менеджер,
  этап (`stage`), статус (label/class), телефон/email, суммы и флаги (call/invoice/paid),
  метки времени (created_at, first_contact_at, stage_entered_at, last_activity_at),
  риск, теги, комментарий AI, `on_dashboard`.
- **stage_history** — переходы сделки по этапам (контроль сроков и «зависших»).
- **tasks** — задачи по сделкам (правило «сделка без задачи»).
- **violations** — нарушения регламента (в боевом режиме вычисляются движком на лету;
  таблица используется для хранения при необходимости).
- **manager_control** — агрегаты по менеджерам (контроль обработки).

### Маркетинг / деньги (`models/marketing.py`)
- **channels** / **campaigns** — витрина каналов и кампаний (расход, лиды, сделки,
  оплаты, выручка, маржа). `spend=NULL` — источник расхода не подключён; `0` — бесплатный.
- **payments** — факт оплаты (Битрикс24 / МойСклад).
- **ad_costs** — расходы/клики/показы Директа по кампании и дню.
- **visits** — визиты Метрики (источник, UTM, цель).
- **calls** — звонки Calltouch (атрибуция источника).
- **products** — номенклатура/бренд/себестоимость МойСклад.

### Аналитика / AI (`models/analytics.py`)
- **baselines** — базовые KPI за 30 дней (пересчёт по периоду множителем).
- **kpi_cards** — карточки KPI дашборда (иконка, тип, спарклайн, drill).
- **ai_insights** — AI-инсайты.
- **budget_recs** — рекомендации AI по бюджету.
- **minus_words** — кандидаты в минус-слова.

### Настройки (`models/settings.py`)
- **regulation_config** — единый версионируемый документ настроек регламента (JSON):
  пороги, правила задач, обязательные поля, график/календарь, правило дублей,
  логика задач, оценочные нарушения.
- **settings_history** — история изменений с данными для программного отката.

## Экспорт актуальной схемы
```bash
docker compose -f docker-compose.prod.yml exec db \
  pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --schema-only > schema.sql
```
